# 微信发送组件启动与恢复

“打开微信”会等待客户端窗口交接并检查 Hook 健康接口。只有组件返回正确版本、就绪状态，而且监听进程属于配置中的匹配微信时才显示成功。微信未登录时可以先完成组件检查，随后在微信中登录，再连接并验证数据库。

如果组件持续无法初始化，在“首次配置”或“工具”中点击“修复微信连接…”。启动错误窗口也会提供该入口：

1. 核对列出的匹配微信进程、路径和 PID。这里仅列出配置中的客户端。
2. 点击“停止选中进程…”，再次确认后才会停止进程，并重新打开匹配微信。可能需要重新登录，未完成的微信操作会中断。
3. 完成微信登录，等待聊天同步，再重试原来的连接或启动服务操作。

修复会保留读取配置、人设、聊天范围和 DSH 会话。其他微信客户端或其他程序不会加入这次修复选择；若存在单实例冲突，请从相应微信托盘退出，或使用原有“检查占用进程”单独处理。

原生 Hook 只保留一个初始化线程。`Weixin.dll` 超过30秒未就绪时，会记录 `module_wait_delayed`，随后低频继续等待，模块出现后再执行一次初始化。已经执行过原生 Hook 安装的失败不会在同一进程中反复安装，需通过上述确认流程重新打开客户端。

应用侧检查仍有约35秒的等待期限，避免界面无限等待；超时不会再使原生模块等待永久失败。不要删除 `manage.ps1` 中的前置检查：30001 是微信内的原生组件端口，8766 是应用适配器端口，二者承担不同职责。

源码修复或新安装包的 DLL 更新需要在匹配微信退出后应用。构建不会直接替换正在使用的客户端 DLL。版本号保持不变；旧安装包不会因源码更新自动包含本次修改。
