# 会话分组与 DSH 工作区

在 WeChatAgent 的“会话”页面管理分组，每个分组对应一个 DSH 工作区。已有 DSH 工作区也会显示，分组数量只统计当前账号聊天范围内的聊天。

## 使用方法

1. 完成微信和 DSH 的连接，在工具页“准备项目配置”，从托盘完整退出并重开 DSH，加载新版插件。
2. 打开“会话”，点击“新建分组”，填写名称并选择一个已存在的文件夹。目录已被 DSH 登记时沿用原工作区与名称。
3. 在现有会话卡片点击“移动到分组”，选择目标并确认。还未初始化的聊天也可以先指定分组，再初始化或等待收到新消息。
4. 点击分组名称筛选会话。可重命名分组；移除空分组只移除 DSH 工作区登记，保留目录和历史文件。

一个工作区可以包含多个私聊或群聊。每个聊天仍有独立上下文、人设、技能与回复规则，分组不会合并聊天历史，也不会自动扩大文件或工具权限。

## 已有会话的历史保留

DSH 0.2.0-rc.2 的会话工作目录属于不可变的创建元数据，不能直接改写旧会话的 cwd。

- 同目录整理：继续使用原会话 ID。
- 跨目录移动：通过 DSH 原生创建接口继承完整事件历史，在目标工作区建立续接会话；确认保存新映射后再归档旧会话。原会话和压缩日志保留，未修改旧日志格式或保护系统消息。
- 新建失败、映射保存失败、账号变化或请求过期：保留原映射；未完成的续接会话不会替代原会话。
- 正在回复或压缩时：拒绝移动并提示稍后重试，不取消正在进行的回复。

历史继承会复制一份会话日志，占用额外 DSH 数据空间，但不会调用模型或产生回复。旧会话可在 DSH 归档记录中查看。移动后的续聊正常使用当前模型，会产生正常模型消耗。

工作区目录用于 DSH 的项目归属和工具相对路径。DSH 会话日志、附件与缓存仍由独立 DSH 的数据目录管理；选择工作区目录不会迁移整个 DSH 数据目录。

## 常见情况

- 看不到工作区分组：先准备项目配置、完整重开 DSH。工作区服务未就绪时，分组功能显示提示，原有聊天仍按原规则处理。
- 工作目录已删除或磁盘未连接：先恢复原目录，再移动；程序不把无法读取的会话当成空历史。
- 分组不能移除：先移走其中尚未归档的 DSH 会话，以及已指定到该组但还未初始化的聊天；其他 DSH 会话也计入保护范围。
- DSH 中刚更名或移动：刷新 WeChatAgent“会话”页面后重试，避免覆盖已经变化的工作区信息。
