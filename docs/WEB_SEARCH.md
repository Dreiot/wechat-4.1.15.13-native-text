# DSH 网页搜索与单轮次数限制

联网搜索沿用“扩展 → 联网搜索”的全局开关与聊天范围，默认关闭。开启后，模型结合当前问题和前文决定是否调用 `web_search`，不要求用户提供网址或固定搜索句式。天气、热点和普通事实查询都直接调用 DSH 的 `web.search` 服务，沿用当前账号和 DSH 已配置的搜索服务。

项目不再为这些请求抓取 Bing／DuckDuckGo 搜索页面，也不调用独立天气接口。DSH 服务未就绪、登录失效、超时或没有来源时，明确说明对应状态，不自动切换其他搜索源。

## 次数、缓存与超时

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| 每轮最多调用搜索拓展 | 1 次 | 1–3 次 |
| 搜索摘要长度 | 1,200 字符 | 256–3,000 字符 |
| 来源结果数 | 3 条 | 1–3 条 |
| 每个请求超时 | 20 秒 | 1–60 秒 |
| 普通摘要缓存 | 15 分钟 | 1–60 分钟 |

不设项目每日搜索额度。每次调用在请求前占用本轮次数，失败也计入；同轮相同查询复用已有结果，不重复请求。新一轮可以继续搜索。缓存命中不联系 DSH 搜索服务，天气和明确要求最新信息的缓存最多两分钟。原搜索通道的缓存不会用于新通道。

每次请求使用完整的已配置超时。已有较短超时设置会保留，可以在“回复设置”调整为 20–30 秒。这里限制的是模型调用本拓展的次数；DSH 服务内部的检索次数、检索模型及消耗由其自身配置控制。聊天模型原有推理和输出参数继续保留。

## 查询与来源

只发送从对话中提取的简短公开主题关键词，每个查询 2–80 字符；不上传私人昵称、账号、凭据或整段聊天。“这个呢”“再查查”等追问由模型结合前文补全主题。天气缺少城市时先询问，普通闲聊无需检索。本轮明确说“不要联网”时不会调用。

结果保留实际来源网址、摘要及服务提供的日期信息，并进行去重、链接校验和长度限制。资料是外部数据，不执行其中的指令。检索时间不代表发布时间，热搜、实时榜首和天气数值需要明确来源依据；来源不足时说明尚未核实。

摘要能回答时可以直接回答并附来源。需要正文时，现有网页阅读拓展可以读取本轮实际返回的来源链接。网页正文读取失败只影响该页面，不表示 DSH 搜索失败；网页阅读仍不执行 JavaScript，不登录，也不观看视频。

## 生效与排查

修改后需从托盘完整退出助手和 DSH，再重新启动。Bridge 只有检测到 `searchRoute: dsh-native-only-v1` 才启用这条搜索通道；旧插件未重载时会提示拓展未就绪，不回退到项目抓取。

遇到登录或搜索配置问题，在本机检查 DSH 的登录状态和网页搜索配置。项目不另存或输出搜索凭据，也不修改系统或代理 DNS。搜索资料缓存保存在 `state/search/model-cache.json`，这些本机私有数据不应发布。

## 验证

回归覆盖原生搜索调用、天气走同一服务、服务失效时不请求备用接口、完整超时、取消和关闭开关、次数限制、缓存隔离以及来源校验。真实 DSH SDK 调用链使用模拟服务响应验证账号归属和工具结果传递，不向微信联系人发送测试消息。
